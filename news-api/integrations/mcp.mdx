The MCP server exposes News API tools to any MCP-compatible client. It handles
authentication, request formatting, and response formatting so the client can
search articles, pull latest headlines and breaking news, look up an author's
work, resolve articles by URL or ID, browse sources, get aggregation counts,
and check subscription/quota status.

| MCP tool | News API endpoint |
| --- | --- |
| `search_articles` | `POST /api/search` |
| `get_latest_headlines` | `POST /api/latest_headlines` |
| `get_breaking_news` | `POST /api/breaking_news` |
| `search_by_author` | `POST /api/authors` |
| `search_by_link` | `POST /api/search_by_link` |
| `list_sources` | `POST /api/sources` |
| `get_aggregation_count` | `POST /api/aggregation_count` |
| `get_subscription` | `POST /api/subscription` |
| `check_health` | *(local liveness ping — no upstream call)* |

Every tool uses `POST` under the hood even though News API also exposes a
`GET` variant of each endpoint — POST keeps API keys and queries out of access
logs, avoids URL-length limits, and lets multi-value filters be sent as native
JSON arrays.

## Before you start

- News API key from
  [platform.newscatcherapi.com](https://platform.newscatcherapi.com/)
- MCP-compatible client (Claude, Cursor, VS Code, Windsurf, Zed, Warp, Gemini
  CLI, Roo Code, or any client that supports remote MCP)

## Authentication

The MCP server resolves your API key from several sources. They are checked in
this order, and the first one present wins:

1. `api_token` parameter set on the tool call itself
2. `?apiToken=YOUR_KEY` URL query parameter — used by Claude.ai, whose
   connector UI does not support custom request headers
3. `x-api-token` HTTP request header — **recommended** for every client that
   supports headers
4. `Authorization: Bearer <key>` HTTP request header
5. `NEWS_API_KEY` environment variable on the server host (self-hosted only)

Most client configurations use option 3 (the `x-api-token` header). Claude.ai
uses option 2 (the `apiToken` query parameter) automatically. `check_health` is
the only tool that does not require authentication — it's a local liveness ping
and never calls News API.

To rotate your key, update your client configuration with the new key and
restart the client.

<Warning>
  The URL query parameter takes priority over the `x-api-token` header. If your
  configured URL still carries `?apiToken=...` from an earlier setup, adding a
  header does not override it — every call fails with `401: Invalid api key`
  naming the old key. Remove the query parameter from the URL when you switch
  to a header.
</Warning>

<Note>
  When you pass the key through a `--header` flag (Claude Code, `mcp-remote`),
  use the `header-name:value` format with no space after the colon — for
  example `x-api-token:YOUR_NEWS_API_KEY`. A space or a missing colon is the
  most common reason a connection silently fails to authenticate.
</Note>

<Warning>
  Your configuration file contains your API key in plain text. Treat it as a
  secret and do not share it or commit it to version control.
</Warning>

<Tip>
  If you are rolling the MCP out to a team, issue a separate API key for it
  rather than reusing a production key. MCP traffic stays attributable in the
  dashboard, and you can rotate or revoke that key without touching anything in
  production.
</Tip>

      </Step>
      <Step title="Configure connection">
        Fill in the **Add custom connector** dialog:

        ```
        https://news-mcp.newscatcherapi.com/mcp?apiToken=YOUR_NEWS_API_KEY
        ```
      </Step>
      <Step title="Add and verify">
        Click **Add**. Verify that News API appears under **Web** in your connectors list.
      </Step>
      <Step title="Test connection">

        Then ask for `get_subscription`. That is the first call that actually uses your key, and it returns your plan, remaining calls, concurrency limit, and how far back you can search.

        Finally, try a real query. Name a time window, a result count, and the fields you want, so the response stays a readable size: "Get the latest headlines about renewable energy from the last 2 days, 10 results, just title, link, date and source."
      </Step>
    </Steps>

      </Step>

## Available tools

Each tool maps to a News API endpoint. For request and response schemas, see
the [API reference](/news-api/api-reference/overview).

| Tool | Description |
|------|-------------|
| `search_articles` | Full-text/boolean search over articles, with date, language, source, entity, and NLP filters |
| `get_latest_headlines` | Recent headlines over a rolling time window, no keyword required |
| `get_breaking_news` | Actively trending, most-corroborated stories over a fixed window |
| `search_by_author` | All articles by one exact byline |
| `search_by_link` | Look up specific already-known articles by NewsCatcher `id` or URL |
| `list_sources` | Browse and verify publishers — requires at least one filter parameter |
| `get_aggregation_count` | Time-bucketed article-volume counts for a query, no articles returned |
| `get_subscription` | Plan tier, monthly quota, remaining calls, concurrency limit, and history window |
| `check_health` | Local liveness ping — no authentication required |

<Note>
  Ask for `get_subscription` before a large pull. It costs one call and tells
  the assistant your remaining quota, your concurrency limit, and how far back
  your plan can search.
</Note>

## Defaults and limits

The MCP passes News API's own defaults straight through, and a few of them
catch people out:

| Behavior | Default | How to change it |
| --- | --- | --- |
| Date range | Last 7 days | Set `from_` and `to_`, e.g. `from_="2026-03-01"` |
| Sort order | `relevancy` | `sort_by="date"` for "latest" or "most recent" |
| Results per call | `page_size=100` (max `1000`) | Lower it for chat-sized answers |
| Clustering | On for `search_articles` and `get_latest_headlines` | `clustering_enabled=false` |
| NLP payload | On | `include_nlp_data=false` |
| Near-duplicate removal | On | `exclude_duplicates=false` |

<Warning>
  The default date range is the **last 7 days**. An undated query about
  something that happened three months ago comes back empty — that is the date
  window, not a coverage gap. Set `from_` and `to_` for anything historical, or
  say the range in your prompt. See
  [Working with historical data](/news-api/guides-and-concepts/working-with-historical-data).
</Warning>

Because clustering is on by default, `search_articles` and
`get_latest_headlines` return `clusters_count` plus
`clusters[{cluster_id, cluster_size, articles}]` — there is no top-level
`articles` list. Keep it on when you want to see which stories got the widest
pickup; pass `clustering_enabled=false` when you want a flat article list. See
[Clustering news articles](/news-api/guides-and-concepts/clustering-news-articles).

Other limits worth knowing:

- There is a hard cap of **10,000 articles per query**, regardless of
  pagination. If `total_hits` reads exactly `10000`, the real count is likely
  higher — narrow the query or split the date range. See
  [Retrieve more than 10k articles](/news-api/how-to/retrieve-more-than-10k-articles).
- Call `get_aggregation_count` first on a broad or undated query to gauge
  volume before paging through results.
- The upstream request timeout is 30 seconds. A `408` means: narrow the query,
  shorten the date range, or reduce `page_size`.

## Keeping responses small

Every tool result lands in your client's context window, and the defaults are
tuned for API clients rather than for chat. A bare `search_articles` call
returns 100 articles wrapped in clusters, each with roughly 30 fields including
the full article text — enough to fill the context window of most clients in a
single call.

Measured against production, same query, same day:

| Call | Response size | Approx. tokens |
| --- | --- | --- |
| `search_articles(q="renewable energy")` | ~1.0 MB | ~262,000 |
| The same query with `page_size=10`, `clustering_enabled=false`, `include_nlp_data=false`, and `fields=["title","link","published_date","domain_url","description"]` | ~5 KB | ~1,400 |

Four levers, in rough order of impact:

- **`fields`** — a list of article keys to keep. Most of the saving comes from
  here, because the default response carries every field including `content`
  and the large `all_links` and `all_domain_links` arrays.
  `["title","link","published_date","domain_url","description"]` covers most
  conversational use.
- **`page_size`** — 10 to 25 is usually right for an answer you are going to
  read.
- **`clustering_enabled=false`** — flat list, no cluster wrapper.
- **`include_nlp_data=false`** — drops the per-article `nlp` object when you
  are not using sentiment, entities, themes, or summaries.

You do not have to name the parameters. Say what you want in the prompt and the
client sets them for you: "20 results, just title, link, date and source, skip
the NLP data."

## Language and country codes

`lang` and `countries` take two-letter codes, never full names. This is the
single most common cause of rejected requests. The MCP checks both before the
call reaches News API and tells you what went wrong:

- **`lang`** — NewsCatcher two-letter language codes: `en`, `es`, `de`. Chinese
  is `cn` (China) or `tw` (Taiwan); the ISO code `zh` is not accepted.
- **`countries`** — ISO 3166-1 alpha-2: `US`, `GB`, `DE`. The United Kingdom is
  `GB`, not `UK`, and three-letter codes are not accepted.

## Quota and rate limits

Every tool call except `check_health` is one billed News API call against your
plan quota. An assistant working through an open-ended question can easily fire
ten or twenty calls in a minute — one to gauge volume, several to page through
results, more to follow up — so the meter moves faster here than it does with
hand-written API calls.

Ask for `get_subscription` at any point to see where you stand:

```json
{
  "active": true,
  "plan": "v3_nlp",
  "plan_calls": 250000,
  "remaining_calls": 249436,
  "concurrent_calls": 5,
  "historical_days": 3000
}
```

- `remaining_calls` — calls left in the current billing period.
- `concurrent_calls` — how many requests you can have in flight at once. Going
  over returns `429`; back off and retry rather than repeating the request
  immediately.
- `historical_days` — how far back your plan can search, which also tells the
  assistant which date ranges are worth trying at all.

## Example prompts

Prompts work best when they name three things: a **time window**, a **result
count**, and the **fields** you want back. These are written for Claude but
work in any client.

**Track coverage of a company or brand**

> What's been published about Siemens Energy in the last 3 days? English only,
> 20 results, just title, link, date and source.

**See which stories got the widest pickup**

> Find coverage of the EU AI Act between 2026-08-20 and 2026-08-27, cluster it,
> and show me the five biggest clusters with their size and one representative
> headline each.

**Read the tone of recent coverage**

> Search for articles about Ryanair from the last 7 days with NLP data on, 50
> results, then list the 10 with the most negative content sentiment and link
> each one.

News API sorts by relevancy, date, or rank — not by sentiment — so the
assistant fetches a page and ranks it itself. Keep the result count modest for
this one.

**Follow a person or organization as an entity**

> Find articles from the last 14 days that name Christine Lagarde as a person
> entity, not just ones that mention the words. 25 results, title, link, date
> and source.

See [Search by entity](/news-api/how-to/search-by-entity) for what entity
matching does differently.

**Measure how a topic trends over time**

> Give me daily article counts for "electric vehicle tariffs" from 2026-06-01
> to 2026-08-31, then tell me which week spiked and what was behind it.

**Catch what is breaking right now**

> What are the biggest breaking stories right now? Headlines and links only.

**Check whether a publisher is indexed**

> Do you index reuters.com, ft.com and nikkei.com? Show me what coverage you
> have for each.

**Pull details for an article you already have**

> Here's a URL: https://example.com/some-article. Pull it and tell me the
> byline, publish date and word count.

<Tip>
  If a result comes back enormous, or your client truncates it, add "10
  results, just title, link, date and source" to the prompt. See
  [Keeping responses small](#keeping-responses-small).
</Tip>

## Troubleshooting

<Accordion title="Tools not appearing">
  Restart your MCP client after updating the configuration. Most clients load
  MCP tools on startup and do not detect changes until restarted.
</Accordion>

<Accordion title="Connection refused or timeout">
  Verify your API key is valid by calling an authenticated endpoint:

  ```bash
  curl -X POST "https://v3-api.newscatcherapi.com/api/search" \
    -H "x-api-token: YOUR_NEWS_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{"q": "test"}'
  ```

  If this returns a `401` error, your key is invalid. Check or reissue it at
  [platform.newscatcherapi.com](https://platform.newscatcherapi.com/).

</Accordion>

<Accordion title="Tool calls returning errors">
  Tools return a pretty-printed JSON string on success. A validation or
  upstream API error comes back as a string starting with `Error: ...`; an
  unhandled exception comes back as `Unexpected error: ...`. The string names
  the specific reason.

  Both are returned as a *successful* tool result — the MCP `isError` flag
  stays `false` — so your client shows an ordinary, completed tool call and the
  assistant may describe the failure as though it were data. When an answer
  looks wrong, open the raw tool output and read the returned string.
</Accordion>

<Accordion title="No results, or only very recent results">
  Queries default to the **last 7 days**. If you asked about something older
  and got nothing back, add an explicit range — "from 2026-03-01 to
  2026-03-31" — and check `historical_days` from `get_subscription` to confirm
  your plan reaches that far. See [Defaults and limits](#defaults-and-limits).
</Accordion>

<Accordion title="429 errors or stalled requests">
  You are over your plan's concurrency limit. Call `get_subscription` and read
  `concurrent_calls` for the ceiling, then back off and retry rather than
  repeating the request immediately. See
  [Quota and rate limits](#quota-and-rate-limits).
</Accordion>

<Accordion title="Response too large, or the client truncated the result">
  The defaults return 100 clustered articles with the full NLP payload and full
  article text. Ask for fewer results and fewer fields — "10 results, just
  title, link, date and source" — or set `page_size`, `fields`,
  `clustering_enabled=false` and `include_nlp_data=false` directly. See
  [Keeping responses small](#keeping-responses-small).
</Accordion>

<Accordion title="401 even though the key is correct">
  Check whether the configured server URL still carries `?apiToken=...`. The
  query parameter takes priority over the `x-api-token` header, so an old
  parameter silently wins over a newly added header. See
  [Authentication](#authentication).
</Accordion>

<Accordion title="Client does not support remote MCP">
  Use `mcp-remote` to proxy the connection. Install Node.js, then use the
  `npx` configuration shown in the **Other clients** tab.
</Accordion>
